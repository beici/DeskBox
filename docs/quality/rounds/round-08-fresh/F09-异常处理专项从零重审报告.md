## 3. 观察项

1. **全局 Handled=true 的僵尸进程风险（设计取舍）**：`App.xaml.cs:4777-4791` 对启动 lifeline 建立后的所有 XAML 未处理异常无条件 `e.Handled = true`，任意 UI 代码抛错后应用带可能不一致的状态继续运行（仅日志）。注释表明这是有意设计（避免持锁无 UI），但一次致命堆栈损坏仍会留下"活着但坏掉"的会话。
2. **本地化 Format 占位符漂移即 FormatException**：`LocalizationService.cs:191-194` `string.Format(CultureInfo..., T(key), args)` 无防御；任一语言文件占位符数量/形态与调用点 args 不匹配即在运行时抛 FormatException（被全局兜底吞掉，功能静默失效）。当前依赖十二语言 key/占位符一致性约束与测试，无运行时自愈。
3. **21 处空 catch 块逐个核实均为正当 best-effort**：日志通道（App.xaml.cs:726/794，日志丢弃可接受）、COM 释放（FolderWatcherService.cs:345）、临时目录/文件清理（NativeDropTarget.cs:1310/1319/1438/1575/1581、DeskBoxDragData.cs:499/521、DirectStartupTaskBackend.cs:414）、Storyboard 停表（WeatherWidgetContent.xaml.cs:117/458/462）、注册表读（Win32Helper.cs:2236）、诊断句柄数（AppDiagnosticsService.cs:139）等，均有安全默认值，无状态不一致。
4. **`_ = ...` 丢弃任务（约 326 处）抽样核验结论**：绝大多数被丢弃方法自带全捕（如 CaptureCurrentClipboardAsync、ScanAsync、ShowSystemContextMenuAsync、UpdateCalendarImagePaletteAsync、ObserveInitializationAndDisposeAsync、RunAutomaticSnapshotIfDueAsync、CloudBackup RunScheduledIfDueAsync）或不可能 fault（DispatcherQueue.TryEnqueue、Task.Delay 无 token）；已立案的例外为 FEXC-01/03/04。UnobservedTaskException 兜底（App.xaml.cs:4803-4807）+ `LogQuickCaptureFailure` 等 ContinueWith 观察器覆盖了其余大部分。
5. **原生层无异常跨界设计**：ShortcutNativeModule 各后端（Shortcut/RecycleBin/QuickAccess/ExplorerShellLaunch/MusicVolume）全部使用 `NativeLibrary.TryGetExport` + 入参校验（长度/嵌入 NUL）+ 返回信封多重校验（结构尺寸/版本/保留字段/volume 范围），失败以枚举+Detail 返回而非异常——异常处理专项角度无缺陷。
6. **休眠路径的小缺口**：`SyncOutboxStore.DequeueAsync`（SyncOutboxStore.cs:129-135）`File.Delete` 无守卫、`DesktopOrganizationRecoveryStore.Clear`（78-87）`File.Delete` 无守卫、`QuickCaptureService.CreateImageExportFileAsync`（366-385）`File.Copy` 无守卫——当前均无生产调用方或仅内部已知上下文，若未来接线需补。
7. **诊断与备份验证细节**：DeskBoxDataBackupService 恢复链路（ Prepare/Apply/Scoped Apply/rollback/重试预算）逐条核实为 fail-closed + 回滚 + 计数器持久化，未见异常分支缺口；`WebDavBackupTransport.ParseMultistatus` 除 FEXC-06 外（如 `Split('/').Last()`、`long.TryParse`）均安全。
8. **FEXC-03 的同构对照**：QuickCapture 详情保存（SaveDetailAsync 全捕 + toast + gate 重入保护）与 Todo 保存（无捕）在同一个 widget 家族里双标，说明 FEXC-03 更可能是遗漏而非有意取舍。

总体评价：异常处理是本仓库工程质量最强的一环——原子持久化协议、备份恢复回滚、原生层结构化错误码、三层全局异常兜底俱备且被广泛正确使用。本次从零审查立案的问题集中在三类模式：fire-and-forget 丢弃点缺 catch 包装（FEXC-01/04）、个别 async void 入口依赖 callee 捕获一切而 callee 并未做到（FEXC-02/05）、以及持久化收口缺少与同级功能一致的失败上报（FEXC-03，附 FEXC-09 协议一致性）。未发现 P0/P1 级别的异常处理缺陷。
