## 2. 问题清单

### FEVT-01 外观预览广播（AppearancePreviewChanged）无异常隔离，且在 Task.Run 内裸触发

- 位置：`src/DeskBox/Services/SettingsService.cs:1281`（`RequestAppearancePreview` 的 `Task.Run` 内）、`SettingsService.cs:1292`（`NotifyAppearancePreviewNow`）
- 触发条件：任一 `AppearancePreviewChanged` 订阅者在回调中抛出异常。该事件在用户调节外观设置（主题/材质/圆角等预览）时高频触发（66ms 防抖广播）。
- 风险等级：P2
- 潜在影响：多播链中排在前面的订阅者一旦抛异常，其后所有订阅者（WidgetManager→全部桌面 widget 窗口的外观应用、SearchPopupWindow 的材质/快捷键提示刷新）当轮收不到通知，UI 出现“部分窗口新外观、部分窗口旧外观”；异常继续沿 `Task.Run` 逃逸为未观察任务异常，被静默丢弃，无任何日志（对照 `SettingsChanged` 有 `App.Log` 日志）。
- 代码层面根因：同一服务内两个姊妹事件走了两套触发纪律——`SettingsChanged` 用 `NotifySettingsChangedSafely`（`SettingsService.cs:1222-1242`，`GetInvocationList()` + 逐 handler try/catch + 日志），而 `AppearancePreviewChanged` 是裸 `?.Invoke()`，且触发点位于 `Task.Run(async ...)` 内，外层只捕获 `TaskCanceledException`：
  ```csharp
  // SettingsService.cs:1274-1287
  Task.Run(async () =>
  {
      try
      {
          await Task.Delay(66, token);
          if (!token.IsCancellationRequested)
          {
              AppearancePreviewChanged?.Invoke();   // ← 1281
          }
      }
      catch (TaskCanceledException) { }
      // Do NOT dispose the CTS here — same rationale as SaveDebounced.
  });
  ```
  对照已隔离写法（`SettingsService.cs:1230-1241`）：
  ```csharp
  Delegate[] handlers = SettingsChanged?.GetInvocationList() ?? [];
  foreach (Action handler in handlers.Cast<Action>())
  {
      try { handler(); }
      catch (Exception ex) { App.Log($"[SettingsService] SettingsChanged observer failed: {ex}"); }
  }
  ```
- 订阅者核实：`src/DeskBox/Services/WidgetManager.cs:672`（`ApplyAppearancePreview`，内部逐窗口 `ApplyAppearancePreview` → `ContentWidgetWindow.xaml.cs:702-708` 已做线程 marshal 但调用链仍可能抛）、`src/DeskBox/Views/SearchPopupWindow.xaml.cs:162`、`src/DeskBox/Controls/DesktopOrganizationTaskView.Appearance.cs:17`。同文件 `NotifyAppearancePreviewNow`（1292）与 `ThemeService.cs:255-275` 的 `RaiseAppearanceChanged`（注释自述“per-handler exception isolation”）进一步说明隔离是本仓库既定纪律，此处为遗漏点。

### FEVT-02 WindowsCompatibilityService 静态事件裸触发（WinRT 回调线程）

- 位置：`src/DeskBox/Services/WindowsCompatibilityService.cs:413-416`（`UiSettings_TextScaleFactorChanged`）、`418-421`（`UiSettings_AdvancedEffectsEnabledChanged`）
- 触发条件：系统辅助功能文字缩放/透明度效果变化，UISettings 事件在非 UI 线程回调（该文件 38-50 行 XML 注释自述回调可能离线到达）。
- 风险等级：P3
- 潜在影响：`TextScaleFactorChanged?.Invoke()` / `AdvancedEffectsEnabledChanged?.Invoke()` 无逐 handler 隔离；任一控件订阅者异常会把异常抛回 WinRT 事件回调（有进程崩溃风险）并截断其余订阅者（其余控件文字缩放不刷新）。当前全部订阅者均做了 dispatcher marshal 与防御（`FileSurfaceContent.TextScaling.cs:64-78`、`WeatherWidgetContent.xaml.cs:115-127`、`DesktopOrganizationTaskView.Appearance.cs:44-51`、`MaterialCapabilityAdvisor.cs:116-124` 经 `App.OnMaterialCapabilitySettingsChanged` 的 TryEnqueue），故实际触发概率低。
- 代码证据：
  ```csharp
  // WindowsCompatibilityService.cs:413-421
  private static void UiSettings_TextScaleFactorChanged(UISettings sender, object args) =>
      TextScaleFactorChanged?.Invoke();

  private static void UiSettings_AdvancedEffectsEnabledChanged(UISettings sender, object args) =>
      AdvancedEffectsEnabledChanged?.Invoke();
  ```
- 附注（配对核实，未立案）：静态事件上的实例订阅均已正确退订——`FileSurfaceContent.TextScaling.cs:16-33`（Loaded 先 `-=` 再 `+=`、Unloaded `-=`）、`WeatherWidgetContent.xaml.cs:96-115`、`DesktopOrganizationTaskView.Appearance.cs:19/33`；`MaterialCapabilityAdvisor.cs:94-101` 用 `Interlocked.Exchange` 保证进程级一次性订阅并注明不退订，符合静态事件语义。

### FEVT-05 Todo 提醒外部变更中继链仅“整体包裹”隔离，单 widget 异常静默截断其余 widget 的合并通知

## 3. 观察项

1. 广播异常隔离纪律不一致（系统性）：仓库已有 7 处“快照 + 逐 handler try/catch + 日志”的成熟写法（`SettingsService.cs:1230-1241`、`ThemeService.cs:255-275`、`LocalizationService.cs:138-157`、`GlanceWidgetStore.cs:324-337`、`FileTransferSessionRegistry.cs:307-326`、`App.xaml.cs:3315-3338` `MemoryCleanupEpochAdvanced`、`Localized.cs:88-110`），但仍有 15+ 个事件为裸 `?.Invoke()`：`QuickCaptureService.cs:1479`、`SearchEngineService.cs:539`、`SearchHistoryService.cs:93/149/216/229/247`、`DisplayAreaWatcherService.cs:212`、`EverythingSearchService.cs:617`、`GlobalHotkeyService.cs:729`、`QuickCaptureClipboardService.cs:256`、`AppUpdateService.cs:598`、`DeskBoxDataBackupService.cs:275`、`CloudBackupService.cs:207/284/358`、`WidgetManager.ZOrder.cs:1329`、`WidgetManager.Groups.cs:2285`、`WindowsCompatibilityService.cs:416/421`、`App.xaml.cs:1838`。已逐一核实这些事件的现有订阅者要么自身做线程 marshal，要么内部全防护，故本轮未逐条立案；但任何新增订阅者都可能在“截断后续订阅者 + 未观察异常”两个面上踩坑，建议收敛为统一 Raise 辅助。
2. `ContentWidgetWindow.RootGrid_PreviewKeyDown`（`ContentWidgetWindow.WindowInteraction.cs:107-135`）为 `async void`；await 的 `TryHandleClipboardShortcutAsync`（`FileSurfaceContent.xaml.cs:4558-4586`）内部经 `RunAsync` 收口，实际风险有限，但模式上与 FEVT-06 同类。
3. `ContentWidgetWindow.ResizeBorder_PointerEntered`（`ContentWidgetWindow.WindowInteraction.cs:326-341`）用反射设置 `ProtectedCursor` 且无 `PointerExited` 复位，光标还原依赖 WinUI“指针离开命中元素即回退”的运行时语义；静态审查无法证实所有平台/触控场景下回退成立，建议留意 Win10 基线的实测表现。
4. `SettingsService.LastNotifiedChangeKind`（写于 `SettingsService.cs:1225-1228`，读于 `ContentWidgetWindow.xaml.cs:1336-1347`）在并发触发时是 best-effort：后到的通知可覆盖先到的 kind，经 `TryEnqueue` 延迟处理的窗口可能读到更新的 kind（appearance-only 判定失真）。现有注释（SettingsService.cs:56-57、429 行）表明这是有意设计，仅记录。
5. `WidgetWindowBase.Interaction.cs:693` `ResizeBorder_PointerCaptureLostCore` 中清除的是拖拽专用字段 `DragCaptureElement`（resize 路径并无该捕获），无害但语义混用，易误导。
6. 控件在 `Loaded/Unloaded` 中对 App 单例事件的订阅（如 `TodoWidgetContent.xaml.cs:180-190`、`GlanceWidgetSettingsSection.xaml.cs:73-84`、`DesktopOrganizationTaskView.Appearance.cs:12-34`）依赖“内容从视觉树移除时 Unloaded 必然触发”这一间接链路（widget 关闭路径经 `ContentWidgetWindow.Closed → WidgetShellContentHost.DisposeContent → _clearContent（shell.ClearContent）` 移除视觉树实现，已核实接线完整）。该模式对“未来任何绕过 DisposeContent 的关闭/复用路径”脆弱，属结构性依赖而非缺陷。
7. 正面核实（记录为基线）：`AppWindow.Changed`、`XamlRoot.Changed`（`WidgetWindowBase.Bounds.cs:396-415`、`DesktopOrganizationPreviewCard.xaml.cs:198-218`）、`CompositionTarget.Rendering`（`QuickCaptureSurfaceContent.xaml.cs:1126/1199`，含隐藏/卸载/释放全路径 detach）等易漏退订点均配对完整；`InlineEditorFocus`（`Helpers/InlineEditorFocus.cs:43-56`）的 Loaded/LayoutUpdated/Timer 三路重试均有 detach 收口；`WeakReference` 各处（`Localized.cs`、`WindowTrackingRegistry.cs`、`WidgetWindowBase.Collapse.cs:1585-1658`、`ExclusiveDropHighlightCoordinator.cs`）均带修剪（prune）逻辑，未发现弱引用列表无界增长。

## 4. 小结

- 统计：P0 = 0；P1 = 0；P2 = 1（FEVT-01）；P3 = 5（FEVT-02 ~ FEVT-06）；观察项 7 条。
- 总体评价：本仓库事件消息层纪律显著高于常见 WinUI 代码水准——拖拽/缩放的 PointerCaptureLost 双路收口、广播事件的线程 marshal、Loaded/Unloaded 与构造/Dispose 的对称退订、弱引用修剪均成体系。立案问题集中在“广播触发纪律未统一”这一条主线上（FEVT-01/02/05 为同一根因的三个体现）与两条死链（FEVT-03/04），另有一处 async void 高频路径（FEVT-06）。无生产环境核心功能失效级（P0/P1）问题。
