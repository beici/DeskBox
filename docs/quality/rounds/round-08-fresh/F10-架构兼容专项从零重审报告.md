### FARC-03 【P2】三处 `UIElement.ProtectedCursor` 字符串反射在 Native AOT 裁剪下可能静默失效（悬停/缩放光标丢失）

- **位置**：
  - `src/DeskBox/Controls/WidgetShell.xaml.cs:5468-5474`（定义；调用点 :401-402 紧凑胶囊移动区/重排把手 `InputSystemCursorShape.SizeAll`）
  - `src/DeskBox/Views/ContentWidgetWindow.WindowInteraction.cs:337-340`（`ResizeBorder_PointerEntered`，按方向设置缩放光标）
  - `src/DeskBox/Views/SearchPopupWindow.xaml.cs:859-864`（`SetPointerCursor`；调用点 :669 顶部拖拽热区及 :850-856 四向缩放边）
- **触发条件**：零售 Native AOT 发布（`PublishAot=true` 全量裁剪）下，反射按名称查找的受保护属性访问器被裁剪元数据。
- **风险等级**：P2（AOT-only、静默 no-op；影响面为三组高频交互光标反馈——内容窗口缩放边框、搜索弹窗缩放/拖拽热区、紧凑胶囊移动把手——属可见但非核心功能的体验缺失；JIT Debug 不会复现，遮蔽性强）。
- **潜在影响**：`property` 为 null → `property?.SetValue(...)` 静默跳过 → 光标恒为箭头，无任何日志或告警。
- **代码层面根因**：WinUI 3 中 `Microsoft.UI.Xaml.UIElement.ProtectedCursor` 为 protected 属性（已核实微软官方文档：`protected InputCursor ProtectedCursor { get; set; }`），C# 侧无法直接赋值，遂以反射绕过：
  ```csharp
  var property = typeof(UIElement).GetProperty(
      "ProtectedCursor",
      System.Reflection.BindingFlags.Instance | System.Reflection.BindingFlags.NonPublic);
  property?.SetValue(element, InputSystemCursor.Create(shape));
  ```
  BindingFlags 本身在 JIT 下正确命中 protected 成员；但在 AOT 全量裁剪下，`GetProperty(string, BindingFlags)` 所需的成员元数据不被任何静态引用 roots（该反射点是全仓对 `ProtectedCursor` 的唯一引用，无 `DynamicallyAccessedMembers` 注解、无 TrimmerRoots），访问器 wrapper 若被裁剪则查找返回 null。且按名称反射不产生 IL2xxx 裁剪告警，零售管线 `publish-aot-retail.ps1:500` 的允许告警码（CS0108/0169/0414/8601/8602/WMC1510）也不会暴露该问题。
- **代码证据**：如上三处源码摘录；`src/DeskBox/DeskBox.csproj:46-57`（审计 profile `PublishTrimmed=true; SuppressTrimAnalysisWarnings=false; TrimmerSingleWarn=false`）；全仓 grep `ProtectedCursor` 仅命中上述 3 个反射点，无任何静态属性访问可为其保根。
- **备注**：三处为复制粘贴的同一模式（一处成三），若确认裁剪成立，修复方向是统一为一个显式 `[UnsafeAccessor]`/`[DynamicallyAccessedMembers]` 或派生类访问器。本报告未运行 AOT 链接器，裁剪是否实际发生留待运行时验证，但「无 root、无注解、无告警暴露」的静态事实成立。

## 4. 小结

本轮从零静态重审了五条「前后端」接口边界与 AOT/架构合规。核心结论：

- **C#↔Rust ABI 冻结契约（ABI 2 / mask 511 / 10 导出）三方完全一致**，能力位检查、信封校验、panic=abort、缓冲所有权纪律均落实到位，未发现签名或布局漂移。
- **Widget 统一内容窗口路径合规**，无遗留宿主复活、无禁用 kind 复活；主要问题是 `current_architecture.md` 交接文档落后代码两个已实现 kind（FARC-02）。
- **更新器/零售管线闭环完整**（清单生成→安装清理→消费互验），架构选择器存在一处共享可变状态副作用（FARC-05）。
- **同步层为「契约先行、PR-1 已入库、引擎未立项」的休眠态**，层内实现与契约一致，但其「不进备份/恢复」边界目前仅靠白名单快照隐式成立（FARC-04）。
- **最重要的代码级风险是 FARC-03**：三处 `ProtectedCursor` 字符串反射在 AOT 全量裁剪下无 root、无注解、无告警暴露通道，一旦元数据被裁即三组高频光标反馈同时静默失效。
- **文档-代码漂移集中于已退役的 search-core**（FARC-01），`native/README.md` 的规范校验命令照做必失败。

统计：**P0=0，P1=0，P2=1（FARC-03），P3=4（FARC-01/02/04/05）**；观察项 12 条。
