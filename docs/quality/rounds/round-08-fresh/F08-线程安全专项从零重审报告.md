## 2. 问题清单

### FTHR-01 Settings 共享 AppSettings 图谱存在绕过 `_lock` 的字段级写入，可与锁内序列化快照构成跨字段撕裂窗口
- 位置：`src/DeskBox/Services/GlobalHotkeyService.cs:253-255`（写入侧）；`src/DeskBox/Services/DesktopDoubleClickActivationService.cs:147`（写入侧）；`src/DeskBox/Services/SettingsService.cs:1074-1131`（`WriteSettingsTempFileAsync` 在 `lock (_lock)` 内序列化同一对象，1082 行）、`src/DeskBox/Services/SettingsService.cs:445-448`（`Settings` getter 返回共享可变实例）。
- 触发条件：热键手势切换/开关切换等直接对 `Settings.X` 赋值的写入不持 `_lock`，而任一其它触发源（拖拽防抖保存、布局保存）恰在此窗口内于线程池执行序列化快照。
- 风险等级：P2。
- 潜在影响：settings.json 被写入「跨字段不一致」的快照（如激活 Kind 已更新而 Modifiers/Key 仍为旧值），崩溃恢复/下次启动时读到非法或错误的组合，导致热键注册失败或行为回退；同类撕裂存在于所有不走 `_lock` 的直接属性赋值点。
- 代码层面根因：`_lock` 只保护部分写入路径（`UpdateWidget` 等），而 `Settings` getter 返回的是同一可变 `AppSettings` 实例；两套写入约定并存，序列化快照的一致性契约只覆盖持锁写入者。
- 代码证据：
  - GlobalHotkeyService.cs:253-255：
    ```csharp
    settings.GlobalHotkeyActivationKind = activation.Kind;
    settings.GlobalHotkeyModifiers = (int)activation.Gesture.Modifiers;
    settings.GlobalHotkeyKey = activation.Gesture.VirtualKey;
    ```
    （三连赋值无 `_lock`；`TryApplyActivation` 的调用方为 UI 线程，但消费方序列化在工作线程）
  - SettingsService.cs:1082-1127：`lock (_lock) { ... JsonSerializer.Serialize(stream, _settings, ...) }` —— 序列化读取的是同一实例。
