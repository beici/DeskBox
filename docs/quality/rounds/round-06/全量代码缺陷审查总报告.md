## 4. P1 问题（3 条，建议立即修复）

### DEF-008 批量边距应用不刷新位置锚点且无屏幕钳制，重启后批量移动整体回退
- **位置**：`Services/WidgetManager.BulkAppearance.cs:114`（`MoveVisibleWidgets`）；`Services/WidgetPositioningService.cs:248-259`（`UpdateConfigFromPhysicalBoundsCore` 仅写 X/Y/W/H）；`Views/WidgetWindowBase.TitleAppearance.cs:516-578`（落点无 `EnsureVisible`）
- **触发条件**：边距对话框勾选"应用到所有"并保存/预览后重启或拓扑切换。被移动格子存在有效锚点时（凡拖拽过/创建定位过的格子均满足），`ResolveBoundsCore` 按旧锚点重建位置，**忽略已持久化的新 X/Y**——批量模式"随布局持久化"承诺 100% 失效。同包缺陷：边距对话框是全仓唯一不做工作区钳制的落点计算，极宽格子 + 大边距可推出屏幕，重启又被拉回（二次漂移）。
- **根因**：批量路径与单格路径（`TitleAppearance.cs:474-475` 先 `CapturePositionAnchor` 再持久化）不对称；窗口自身 `OnAppWindowChanged` 非拖拽早退，不补采。审查期间整改已补位置锁与压缩态守卫（`BulkAppearance.cs:72-74`），唯锚点与钳制仍缺。
- **影响**：已交付功能 BATCH2-F1 批量模式核心承诺失效（P1 定级依据，S4 定 P1 / S7 定 P2，从用户承诺失效角度取 P1）；组宿主被移动时 `WidgetGroupConfig.X/Y` 亦不同步。
- **建议**：`MoveVisibleWidgets` 成功分支补 `CapturePositionAnchor` 语义（复用 `WidgetPositioningService.CaptureAnchor`），组宿主同步 `SynchronizeGroupLayoutFromMember`；落点套 `EnsureVisible`；补"批量边距→重启→位置保持"回归用例。
- **来源**：S04 LAY-01/LAY-03 + S07 CFG-01（合并）

### DEF-009 随记剪贴板写入未标记"自写"，开启记录后每次复制必自我回录垃圾记录
- **位置**：生产宿主 `Controls/WidgetContents/QuickCaptureSurfaceContent.xaml.cs:2603-2608`（选中复制 `DataPackage` → `SetContent` 无标记）；死代码宿主内另有 2 处（`QuickCaptureWidgetWindow.SelectionAndDrop.cs:343`、`Items.cs:476`，随 ARC-01 清理消除）
- **触发条件**：用户开启"随记剪贴板记录"后执行任意复制操作（多选复制/OCR 取字/Surface 选中复制）。
- **根因**：自写忽略机制依赖写侧配对标记（`DeskBoxClipboardWriteScope.MarkWrite`）；同类复制路径 `Operations.cs:407-413` 已正确标记，上述位点为遗漏（Surface 与死窗口两套平行实现漂移放大遗漏面，QC-15）。
- **影响**：每次操作必现一条垃圾记录并持久化；OCR 结果覆盖用户剪贴板原文的记录语义。
- **建议**：复制路径统一收敛到 ViewModel 层 `CopyItemAsync`（已含标记），或写入点补 `MarkClipboardTextWrittenByDeskBox`。**移交核查**：`SearchPopupWindow.xaml.cs:3604/3827/4061` 三处剪贴板写入疑似同型遗漏（S5 移交），修复时一并核验。
- **来源**：S05 QC-01

### DEF-010 启动路径在线程池线程刷新主题：跨线程 WinUI 访问 + 无锁集合并发 + 托盘订阅者无投递保护
- **位置**：`App.xaml.cs:941`（`Task.Run(() => themeService.RefreshAppearance())`）；`Services/ThemeService.cs:206-211`（遍历 `_trackedWindows` 读 `window.Content`/写 XAML 属性 + 裸广播）；`App.Tray.cs:849-858`（托盘订阅者直接改 `_trayIcon.Icon`，无 TryEnqueue）
- **触发条件**：**每次应用启动必现**（确定性路径）。
- **根因**：启动并行化把整个必须 UI 线程执行的刷新整体丢进线程池；`_trackedWindows` 为无锁 `List<Window>`，与 UI 线程 `TrackWindow`（:945）并发 Add/枚举。
- **影响**：`RPC_E_WRONG_THREAD` 异常/渲染状态破坏/List 并发异常（可抛 `InvalidOperationException`）；`AppearanceChanged` 在后台线程触发使无保护的托盘订阅者跨线程操作句柄。
- **建议**：最小修复——`Task.Run` 只包离线工作（读系统色值），`RefreshAppearance` 留 UI 线程；或入口补 `HasThreadAccess` + TryEnqueue 重投并给 `_trackedWindows` 加锁。一行级改动即可消除。
- **来源**：S08 THR-01
