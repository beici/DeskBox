## 2. 契约对照结论

### A. Rust ↔ C# 契约 —— **一致，未发现契约漂移**

| 核对项 | 契约（头文件/README） | Rust 实现 | C# 调用方 | 结论 |
|---|---|---|---|---|
| ABI 版本 | `DESKBOX_NATIVE_ABI_VERSION 2u`（deskbox_native.h:6） | `lib.rs:15` `= 2` | `ShortcutNativeModule.AbiVersion = 2`（ShortcutNativeBackend.cs:146），加载时 probe 比对 | 一致 |
| Capability mask | `511`（9 位，h:14–41） | `lib.rs:22–41` 同 9 位掩码合成 | 每个 backend 按位检查自己的 capability（Shortcut 1<<0..1<<4、Music 1<<5、Explorer 1<<6、QuickAccess 1<<7、RecycleBin 1<<8） | 一致 |

| 函数指针调用约定 | `__cdecl` | `extern "C"` | `delegate* unmanaged[Cdecl]<...>` 全部 10 个 | 一致 |
| 结构体布局 | h:171–421 定义 16 个结构体，64 位下带 `static_assert` 大小 | `lib.rs:162–467` `#[repr(C)]` 同布局，测试中 `assert_eq!(size_of::<...>())`（lib.rs:1906+） | 16 个 `StructLayout.Sequential` 结构体逐字段比对（字段名/类型/顺序/reserved 全等） | 一致，逐字段核对无漂移 |
| 错误码 | `DESKBOX_NATIVE_STATUS_*` 0–9、HRESULT 常量 | 同常量（lib.rs:43–59） | C# 侧校验 `returnedStatus == result.Status`、`struct_size/version` 回读（防缩短/降版本返回） | 一致 |

| 字符串/缓冲区所有权 | "caller-owned output buffers ... Rust-owned strings must not cross the boundary" | 读操作写入调用方 `DeskBoxNativeUtf16BufferV1`（C# `char[]` pin），写操作借用 C# 字符串；Rust 不保留任何指针 | `ShortcutNativeBackend.Invoke` 中 `fixed` pin + `TryDecode` 校验 required_chars ≤ 缓冲长度且以 `\0` 结尾 | 一致 |
| thumbnail-proxy 进程契约 | 独立 exe；argv 协议（`--self-test` / `--context-menu path x y` / `[--icon-only] path size`）；stdout 输出 BMP V5 payload；上下文菜单退出码 0=Invoked / 2=Cancelled / 3=Failed | `deskbox-thumbnail-proxy/src/main.rs:208–271`（解析）、`411`（`ready\n` 握手）、`199–205`（退出码） | `ShellContextMenuProxy.MapExitCode`（0/2/3 → Invoked/Cancelled/Failed）、`ShellThumbnailProxy` 要求 `ExitCode==0` + 可见位图载荷；CSHTML exe 由 MSBuild 目标以 `DeskBox.ThumbnailProxy.exe` 产出并接入 csproj（DeskBox.csproj:140–167） | 一致 |

## 5. 结论

架构整体健康度：**良好（结构层）/ 需要一次文档追平（契约层）**。

1. **冻结契约（Rust ↔ C# FFI）零漂移**：ABI 2、capability mask 511、十导出、16 个结构体布局、错误码、panic=abort、调用方持有缓冲的所有权模型，在头文件、Rust 实现、C# 调用方三方逐项一致；thumbnail-proxy 进程契约（argv + BMP V5 stdout + 退出码）双侧吻合。这是本仓库最核心的跨语言边界，现状可放心维持。
2. **扩展面（widget 管线）结构完整**：五张注册表互相一致，占位 kind 的扩展路径安全，legacy `Productivity`/`WidgetWindow` 未复活；唯一的结构性问题是 QuickCapture 宿主迁移完成后文档与死代码未追平（ARC-01，本轮最高风险项，P2）。
3. **兼容性纪律执行到位**：Win10 21H2 下限通过集中式 `WindowsCompatibilityService` + `TrySetDwmWindowAttribute` 白名单守卫落实，未发现无守卫的 Win11-only 调用；AOT 敏感面（dynamic/ComImport/反射/JSON）全部处于条件编译或源生成保护之下。
4. **更新与安装链路契约闭环**：manifest 生成（publish-aot-retail.ps1）→ 安装器消费（iss BeforeInstall）→ 清理脚本硬校验，三方一致。
5. **卫生项集中且低危**：3 个未接线 DI 注册、7 处工厂重复实例化、1 个无生产调用方的缓存类、2 类文档漂移——均为 P3，不影响生产功能。

问题计数：**0×P0，0×P1，1×P2（ARC-01），5×P3（ARC-02～06）**。
