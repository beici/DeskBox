### QC-01 三处剪贴板写入未标记"自写"，开启剪贴板记录后自我回录

- 【位置】`Views/QuickCaptureWidgetWindow.SelectionAndDrop.cs:343-352`（`SetClipboardText`，被 `CopySelectedQuickCaptureItemsAsync` 多选路径调用，305-336）；`Views/QuickCaptureWidgetWindow.Items.cs:476-478`（`CopyImageTextAsync` OCR 文本）；`Controls/WidgetContents/QuickCaptureSurfaceContent.xaml.cs:2431-2434`（Surface 选中复制，单项文本与多项均走此路径）
- 【触发条件】用户开启"随记剪贴板记录"（`QuickCaptureClipboardEnabled`，默认关、Recent 空态按钮一键开启）后，执行多选复制（Ctrl+C / 右键菜单"复制 N 项"）或图像 OCR 取字复制。
- 【风险等级】P1
- 【潜在影响】`Clipboard.ContentChanged` 触发采集链，`DeskBoxClipboardWriteScope.ShouldIgnore` 因无标记而放行，把这批刚复制的内容（含分隔符与附件路径的合成文本）作为一条新"最近记录"写入随记数据并持久化——每次操作必现一条垃圾记录，且 OCR 结果会覆盖用户剪贴板原文的记录语义。
- 【根因说明】自写忽略机制靠写侧配对标记（`MarkWrite`/`MarkText`）。同为复制路径的 `ViewModel.CopyItemAsync`（Operations.cs:388/401/409）、`DetailCopyButton_Click`（Attachments.cs:51-53）、附件图像复制（Attachments.cs:218）均已标记，上述三处为遗漏；Surface 与 Window 实现漂移放大了遗漏面（Window 单项复制走已标记的 `CopyItemAsync`，Surface 单项文本复制直接 `SetText` 不标记）。
- 【整改建议】三处写入后统一调用 `App.Current.QuickCaptureService?.MarkClipboardTextWrittenByDeskBox(text)`（或直接 `DeskBoxClipboardWriteScope.MarkWrite`）；Surface 选中复制收敛到与 Window 相同的 `ViewModel.CopyItemAsync` 复制路径。
- 【证据】

### QC-05 对比度校验仅作用于保存时刻；主题切换可产生功能本要杜绝的不可读配色

- 【位置】`Views/QuickCaptureWidgetWindow.Appearance.cs:650-663`（保存时校验）、`:557-592`（`ApplyClipboardItemColors` 应用时不校验）
- 【触发条件】深色主题下为记录文字设置自定义浅色（对深色卡片背景通过 ≥1.3 校验）→ 系统切换浅色主题 → 背景通道为"跟随主题"自动变为浅色卡片 → 自定义浅色文字 × 浅色背景对比度跌破 1.3。反向（浅存深、切深）同理。
- 【风险等级】P2
- 【潜在影响】恰好复现 BATCH2-F2 要杜绝的"文字完全不可读"组合，且用户在切换主题前无法预见；设置面板不再打开也会发生。
- 【根因说明】校验点在 `ShowClipboardItemColorPickerAsync` 的保存分支；单通道为跟随主题时，其生效色随主题变化，而配对的另一通道是静态自定义色，二者组合的有效性从未在主题切换路径复检。

## 5. 结论

1. **总体判断**：随记功能核心链路（剪贴板监听→解析→去重入库→展示→编辑→Markdown 渲染→附件管理）架构清晰、防御面较全（读写重试、引用扫描 GC、AOT smoke 契约、12 语言覆盖），未发现 P0 级失效。
2. **BATCH2-F2 复核**：全链实现与设计文档一致，回归结论可信；发现 1 条设计边界缺口（QC-05，主题切换后对比度失效）需小补。胶囊态右键菜单时序在正常路径无根因残留，残留面收敛为低频竞态 QC-09。
3. **最值得优先修复**：QC-01（3 处剪贴板写入漏标记自写，启用记录功能后高频自我回录）与 QC-02（详情编辑静默改写条目内容格式），二者都是高频用户路径上的数据污染类缺陷。
4. **问题计数**：15 条（P1×1：QC-01；P2×4：QC-02/03/04/05；P3×10：QC-06~15）。
