## 2. 已知问题复核

### 2.1 DEF-001（显示桌面后部分格子不显示）—— 修复健壮，回归面见 WIN-04

代码级复核结论：**链路三要素在 HEAD 全部在位且正确**。

1. **Hook 注册线程**：`WidgetShowDesktopSelfHealService.Start()` 显式区分 `HasThreadAccess`，非 UI 线程续体经 `_dispatcherQueue.TryEnqueue(StartCore)` 回 UI 线程注册（`WidgetShowDesktopSelfHealService.cs:59-66`），并有注释说明"线程池注册的 OUTOFCONTEXT hook 收不到事件"的原始缺陷。回调与 debounce 全部落在 UI 线程消息循环。
2. **事件常量**：`EVENT_SYSTEM_FOREGROUND = 0x0003`、`EVENT_SYSTEM_MINIMIZESTART = 0x0016`、`EVENT_SYSTEM_MINIMIZEEND = 0x0017`（`Win32Helper.cs:257-259`），与 winuser.h 一致（R2 修正后的 0x0016 正确；注意 `AppLifecycleRecoveryWatcher.cs:14` 的 `WmEndSession = 0x0016` 是窗口消息空间，与 WinEvent 空间无冲突，均为正确值）。flags 使用 `WINEVENT_OUTOFCONTEXT | WINEVENT_SKIPOWNPROCESS`，`idObject != 0` 过滤。
3. **验证/恢复动作**：`VerifyRestingWidgetsAfterShellMinimize`（`WidgetManager.ShowDesktop.cs`）四道保守门（raised / toggling / interaction / `ShouldKeepWidgetsVisibleOnShowDesktop`），对 iconic 走 `SW_SHOWNOACTIVATE` + `MoveToDesktopBottom`（重挂 Explorer 桌面 owner，防再次裸露），对 shell cloak 走 `DWMWA_CLOAK=0`；自托盘隐藏造成的 cloak 经 `IsTrayCloakActive` 豁免（`WidgetWindowBase.cs:56`）。与台账"链路三要素 + 正向恢复用例"结论一致。
4. **生命周期**：服务在 `ShutdownApplicationAsync` 中 Dispose 且 Unhook 两枚 hook（`App.xaml.cs:3687-3688`），无泄漏。

回归面：hook 注册失败无检测、无重试（见 WIN-04）；`IsWidgetInteractionActive` 期间跳过的验证会在下一次前台事件 700ms 后补跑，可接受。

### 2.2 DEF-002（胶囊悬停自动展开偶现无响应）—— 修复在 HEAD 且覆盖完整

### 【WIN-05】[重要勿删] 文档与代码失同步：`EnsureRaisedFromTrayTopMost` 的 `_isAtDesktopLayer` 短路已不存在

- **位置**：`src/DeskBox/Views/ContentWidgetWindow.xaml.cs:926-937`、`src/DeskBox/Views/QuickCaptureWidgetWindow.xaml.cs:489-509`（对照文档 §3.3 第 3 步）
