### DEF-003（胶囊悬停展开逐帧开销 → 已闭环，R4 实测 dropped=0）

**复核结论：修复代码健壮，机制完整，未发现回归风险。** 逐项确认：

1. **每帧不再写布局/外观依赖属性**：`StartCompactCompositionTransition`（`Controls/WidgetShell.xaml.cs:1912-1979`）为 Win10 与 Win11 统一启用独立合成动画——7 个层用 `ScalarKeyFrameAnimation` 预烘焙 12 个关键帧（`StartCompactOpacityAnimation`，1986-1999），full-bleed 背景/叠加层附加 Scale（24 关键帧）+ Opacity。`SetCompactTransitionProgress`（`Controls/WidgetShell.xaml.cs:1819-1905`）在 `_isCompactCompositionTransitionActive` 为 true 时完全跳过 Opacity/Translation/圆角/全出血的逐帧 DP 写（注释明确指向帧成本修复）。UI 线程每帧只剩 HWND 边界插值 + `MoveWindowWithoutPersisting`。
2. **HWND 批量提交与零分配优化**：帧内 `TryQueueBoundsMove`（`Services/WidgetCompactAnimationCoordinator.cs:101-122`）收集所有并发胶囊的边界，帧尾 `FlushPendingBoundsMoves`（374-431）以单个 `BeginDeferWindowPos/DeferWindowPos/EndDeferWindowPos` 原子提交，失败回退逐个 `SetWindowPos`；值缓冲复用（`PendingBoundsMovesBuffer`，381-385 注释明确记载了移除每帧分配的优化）。
3. **启动/停止/中断状态机严密**：
   - 注册：`RegisterBoundsTransition` 有并发上限（`MaximumConcurrentBoundsTransitions = 4`，含 `InvalidOperationException` 防御）；
   - 停止：`StopCollapseAnimation`（`Views/WidgetWindowBase.Collapse.cs:3720-3744`）Dispose 帧注册、取消 watchdog、取消/完成 shell 转场；

4. **帧率与跳帧策略有界**：`WidgetCompactFrameSkipPolicy` 仅在 8 tick 窗口内 ≥6 次超预算（1.5× 帧预算）时逐级降档（满帧→60fps→30fps），进度按时间计算，时长/缓动不受影响；`WidgetCompactAnimationFrameTracker` 零分配记录，`dropped` 指标链路（R4 的 A/B 依据）完好。
5. **Win10 回退路径完好**：`WidgetCompactAnimationCoordinator` Win10 优先用 DwmFlush 后台线程按 DWM 呈现节奏入队 tick（180-261），DwmFlush 失效（dwmal 不可用 / instant-flush ≥30 / enqueue 失败）时**本会话永久**切换为刷新率推导的 DispatcherQueueTimer（204-218, 269-292）；线程为后台 + `AboveNormal`，且仅在动画期间存活（`StopFrameClock` 485-506 收回）。tray 批量动画在 Win10 用 `Clamp(1000/refreshHz, 8, 16)` 的 DispatcherQueueTimer（`WidgetTrayBatchAnimationDriver.cs:114-140`），≤16ms 间隔守住 60fps 红线。合成 Opacity 动画本身 Win10 同样启用（1919-1928 注释明确"both run the independent fades on the compositor clock"），回退仅针对帧时钟与异常路径（`StartCompactCompositionTransition` catch → DP 写回退分支，`SetCompactTransitionProgress` 1832-1874 保留完整的非合成实现）。

### 【ANI-01】胶囊常驻氛围效果用 20Hz CPU 计时器逐拍写 Opacity，持续阻止渲染空闲

- **位置**：`Controls/WidgetShell.xaml.cs:2905-2931`（live breathing）、`:3416-3441`（bottom glow）、`:3473-3502`（breath border）。
- **触发条件**：任一格子处于胶囊（collapsed）态且启用对应氛围效果——live 状态指示（呼吸点）、底部辉光、搜索/边框呼吸。默认（Balanced 档）`AllowCompactAmbientAnimations=true`。
- **风险等级**：**P2**（低频/边界场景：仅带 live 状态/搜索边框的胶囊格子；持续性能与能耗影响）。
- **潜在影响**：每个动画中的胶囊各自挂一个 50ms（20Hz）`DispatcherQueueTimer`，每拍执行一次 `Opacity` DP 写 → 每秒 20 次 UI 线程唤醒 + 20 次合成器脏区更新，桌面常驻格子阻止 UI 线程与 DWM 进入空闲。多个此类格子叠加时线性放大；与 tray 滑动、胶囊转场等 CPU 驱动动画争用 UI 线程时间片。这与 DEF-003 的修复方向（把持续性视觉运动下沉到合成器时钟、让 UI 线程零参与）相悖——呼吸/辉光是典型的可用 `ExpressionAnimation`（以 `StartingValue + Amp*sin(phase)` 绑定动画时钟）或无限 `ScalarKeyFrameAnimation` 完全脱离 CPU 的效果。
- **根因说明**：氛围效果实现早于合成器动画收敛，迁移 DEF-003 时未覆盖常驻类装饰动画。
- **整改建议**：将三个计时器效果改写为合成器动画：呼吸类用 `Compositor.CreateExpressionAnimation`（`Math.Sin` 于 `Animation.Duration` 相位）或 `IterationBehavior.Forever` 的 ScalarKeyFrame 循环，直接绑到 `visual.Opacity`；保留现有的启动门槛（collapsed/可见/系统动画开启/PerformanceMode 开关）作为 Start/Stop 条件。收益：UI 线程每秒 20 次唤醒归零，动画跟随显示器刷新率更平滑。
- **证据**：

```csharp
// Controls/WidgetShell.xaml.cs:2905-2930
_compactLiveBreathingTimer = DispatcherQueue.CreateTimer();
_compactLiveBreathingTimer.Interval = TimeSpan.FromMilliseconds(50);
_compactLiveBreathingTimer.Tick += CompactLiveBreathingTimer_Tick;
...
private void CompactLiveBreathingTimer_Tick(DispatcherQueueTimer sender, object args)
{
    _compactLiveBreathingPhase += 0.06;
    CompactLiveProgress.Opacity =
        0.6 + 0.2 * Math.Sin(_compactLiveBreathingPhase);
}
```

  同构代码在 `BottomGlowTimer_Tick`（3432-3437）与 `BreathBorderTimer_Tick`（3495-3500）。缓解因素（已确认）：三个计时器均要求 `_isHostVisualActivityEnabled && IsLoaded && _isCollapsed && CompactAmbientAnimationsEnabled() && SystemAnimationsEnabled()` 才启动，`SuspendVisualActivity`/`PerformanceSettingsPolicy`（ResourceSaver 档 `AllowCompactAmbientAnimations=false`）与用户级 `EnableCompactAmbientAnimations` 开关可关闭。

### 【ANI-03】悬停展开每帧回调路径存在每帧委托/闭包分配

- **位置**：`Views/WidgetWindowBase.Collapse.cs:3687-3693`（`MoveWindowWithoutPersisting` → `TryQueueBoundsMove` 的三个 lambda）。
- **触发条件**：任一胶囊展开/收起转场的每一帧（每个动画窗口每帧一次）。
- **风险等级**：P3。
- **潜在影响**：每帧每窗 3 个委托分配 + 1 个闭包对象（`fallback` 捕获逐帧变化的 `bounds`，必然新分配；`beforeCommit`/`afterCommit` 仅捕获 `this`，C# 编译器对实例捕获 lambda 不做缓存）。60-144fps 下每窗每秒约 240-860 次小对象分配，量小但与项目自身的分配纪律不一致——同一条管线在 `WidgetCompactAnimationCoordinator.FlushPendingBoundsMoves`（:381-385）专门为移除每帧 `Values.ToArray()` 做了缓冲复用优化。
- **根因说明**：批量提交 API 设计为每帧传参，未提供委托复用通道。
- **整改建议**：为 `MoveWindowWithoutPersisting` 缓存两个实例级委托（`beforeCommit`/`afterCommit` 只捕获 `this`，可存字段）；`fallback` 改为无捕获实例方法 + 每帧写入一个可变字段，或给 `PendingBoundsMove` 增加"失败后由协调器回调窗口重试"的接口以消除闭包。收益是转场期间 Gen0 分配归零，非紧迫。
- **证据**：

```csharp

    HWnd,
    bounds,
    flags,
```

### 【ANI-05】胶囊转场中断时透明度从固定曲线起点跳变（快速悬停进出的视觉衔接）

- **位置**：`Controls/WidgetShell.xaml.cs:1986-1999`（关键帧曲线从 profile 起点烘焙）、`:2088-2107`（`ResetCompactTransitionVisuals` 先将各层 Opacity 全部重置为 1）。
- **触发条件**：转场进行中发生反向转场（如展开至中途用户移出指针触发收起，或 Smart 行为的快速进出）。高频悬停抖动场景。
- **风险等级**：P3（观察项；未实测，感知风险低——转场仅 120-400ms）。
- **潜在影响**：合成动画的 12 个关键帧是预烘焙的固定曲线，关键帧 0 对应新方向 progress=0 的值，而非中断时刻各层的实际视觉值。中断瞬间（`StopCollapseAnimation` → `CancelCompactTransition` → `ResetCompactTransitionVisuals`）先把所有层 Opacity 复位为 1，再由新方向动画跳到曲线起点。例如展开进行到 60% 时紧凑层已淡至约 0.2，反向收起开始时紧凑层 Opacity 先跳回 1——快速连续进出时可能观察到一次不透明度闪跳。状态机的逻辑正确性（generation/stop/重启）无问题，纯视觉衔接问题。
- **根因说明**：预烘焙关键帧方案（DEF-003 修复）天然不带"从当前值开始"能力；未使用 `ExpressionAnimation` 以当前值为基的接续。
- **整改建议**：仅在实测确认可感知后再处理：中断重启时以"当前 `visual.Opacity`"作为新动画的第一个插值锚点（读取 `ElementCompositionPreview.GetElementVisual(el).Opacity` 作为关键帧 0，其余关键帧按剩余进度重排），或改用 `ExpressionAnimation` 驱动的相对插值。
- **证据**：

### 【ANI-06】栈成员动画启用 Translation 后不复位（SetIsTranslationEnabled 残留）

- **位置**：`Controls/WidgetContents/FileSurfaceContent.StackAnimations.cs:270`（`StartStackElementAnimation` 内 `SetIsTranslationEnabled(element, true)`），对照 `:349-351`（`RestoreStackAnimationElement` 仅复位 Translation 值，不关闭开关）。
- **触发条件**：任一文件栈成员播放收起/切换动画后，该视觉元素长期保留 Translation 属性启用态。
