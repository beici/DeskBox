### THR-01 热键钩子同步握手与线程 Join 仍是 UI 线程主路径，钩子线程假死时可冻结 UI 约 2.15 秒

- 【位置】`src/DeskBox/Services/ReservedHotkeyHookService.cs:187`、:325、:363；`src/DeskBox/Services/DesktopDoubleClickActivationService.cs:251`、:352、:368；同步调用点：`src/DeskBox/Services/GlobalHotkeyService.cs:156`、`src/DeskBox/Services/SearchHotkeyService.cs:150`、`src/DeskBox/Services/DesktopDoubleClickActivationService.cs:163-171`、`src/DeskBox/Views/OnboardingWindow.Hotkey.cs:94`、`src/DeskBox/Views/SettingsWindow.HotkeyAndAppearance.cs:361`
- 【来源】round-06 THR-02 **维持**（异步变体已落地但未被主路径采用）
- 【触发条件】a) 设置页改热键手势 / 触发 `GlobalHotkeyService.RefreshRegistration`（`App.xaml.cs:1628-1630` 生命周期恢复、`GlobalHotkeyService.cs:96/:242/:266/:278/:299`）；b) 开启/关闭双击桌面激活（`DesktopDoubleClickActivationService.RefreshRegistration:163` → `TryStart:171`）；c) 开始录制热键（Onboarding/Settings 直接 `TryStart`）；d) watchdog 恢复（`HookHealthWatchdog.cs:239-257` 投 UI 线程后同步走同一路径）。
- 【风险等级】**P2**
- 【潜在影响】全部调用点在 UI 线程：`Stop()` 的 `thread.Join(StopTimeoutMilliseconds)`（500ms）+ `thread.Join(ForcedStopTimeoutMilliseconds)`（150ms）+ `TryStart` 的 `ready.Task.Wait(1500ms)`——低级键盘钩子回调被系统串行化、Explorer 假死或解锁恢复场景下 UI 冻结最长约 2.15 秒，表现为设置页/热键切换/解锁恢复瞬间卡死。
- 【代码层面根因】同步签名 `bool TryStart(...)` 的启动握手用 `TaskCompletionSource.Wait(timeout)`、停止用 `Thread.Join`，而非异步等待；异步变体（`ReservedHotkeyHookService.cs:210-266`、DDCA :275-302）已存在但 `RefreshRegistration`/录制钩子未切换。
- 【代码证据】
  ```csharp

  if (!ready.Task.Wait(StartupTimeoutMilliseconds))   // UI 线程同步阻塞，最长 1500ms
  ```

### THR-02 群组拖出预览：后台 16ms 轮询在 lock(_gate) 内跨线程 SetWindowPos/ShowWindow，与 UI 线程同锁持有者互等

- 【位置】`src/DeskBox/Views/WidgetWindowBase.Grouping.cs:516-545`（`Task.Run` 轮询循环，:536-542 调 `preview.Update`）；`src/DeskBox/Views/WidgetDetachPlacementPreviewWindow.cs:153-173`（`Update` 全程 `lock (_gate)`）→ `MoveAndShowNoLock`（:261-299，`SetWindowPos` :269/:290）与 `HideNoLock`（:301-310，`ShowWindow` :308）；UI 线程同锁持有者：`Hide`（:230-242）、`Dispose`（:244-259）、`FadeOutAndHideAsync`（:193-228）

- 【触发条件】拖出群组预览进行中（后台循环每 16ms 一次），同一毫秒窗口内 UI 线程进入 `Hide/Dispose/FadeOutAndHideAsync/MarkCommitted` 抢同一把 `_gate`。
- 【风险等级】**P2**
- 【潜在影响】预览 HWND 归 UI 线程所有，跨线程 `SetWindowPos/ShowWindow` 向属主线程同步发消息（WM_WINDOWPOSCHANGING/CHANGED）；后台线程持 `_gate` 等 UI 泵消息、UI 线程等 `_gate` → 双死等，只能杀进程。触发需毫秒级窗口、概率低后果重。
