### QC-01 多选复制剪贴板写入无重试、无异常保护，经 async void KeyDown 上抛未观察

- 【位置】`src/DeskBox/Controls/WidgetContents/QuickCaptureSurfaceContent.xaml.cs:2764-2771`（`CopySelectedQuickCaptureItemsAsync` 写剪贴板段）；调用链 `:2689-2704`（`ItemsList_KeyDown`，`private async void`，Ctrl+C 分支 :2699-2703）
- 【触发条件】列表多选后按 Ctrl+C（或单选非图像文本项）执行复制，剪贴板恰被其它进程短时锁定/占用（`Clipboard.SetContent`/`Clipboard.Flush` 抛 COMException 0x800401D0）。
- 【风险等级】P3
- 【潜在影响】异常从 `CopySelectedQuickCaptureItemsAsync` 直上 async void `ItemsList_KeyDown` 未观察通道，落入全局兜底（App 层 `Handled=true`，不崩溃、仅日志）；用户表现为复制偶发静默失败、无任何提示。对照：单项复制路径有 4 次退避重试 + `RunAsync` 全 catch + 失败 toast（`Operations.cs:355-378`、surface `:3545-3559`），两路径防御不对称；自写标记本身已正确（:2769），无回录问题。
- 【代码层面根因】该写入点是多选复制收敛进 Surface 时新写的独立 `DataPackage` 段，未复用 `WriteItemToClipboardWithRetryAsync` 的重试包装，也未置于 `RunAsync` 之内。
- 【代码证据】
  ```csharp
  // QuickCaptureSurfaceContent.xaml.cs:2764-2771 —— 有 MarkWrite，无重试、无 try/catch
  var dataPackage = new DataPackage { RequestedOperation = DataPackageOperation.Copy };
  dataPackage.SetText(text);
  DeskBoxClipboardWriteScope.MarkWrite(text: text);

  // :2689  private async void ItemsList_KeyDown(...) { ... :2699-2703 await CopySelectedQuickCaptureItemsAsync(); }
  ```
- 【整改建议】将写剪贴板段包入 try/catch 并 toast 失败，或收敛到 `WriteItemToClipboardWithRetryAsync` 复用重试。

### QC-02 设置入口配色编辑器的取色器初始值与对比度校验基线硬编码深色主题常量，浅色主题下失真

- 【位置】`src/DeskBox/Views/SettingsWindow.QuickCaptureColors.cs:87-94`（`ResolveQuickCaptureEffectiveTextColor` 回退 `0xFFF5F5F5`）、`:96-103`（`ResolveQuickCaptureEffectiveBackgroundColor` 回退 `0xFF282828`）；消费点 `:61-70`（作为 `QuickCaptureClipboardColorEditor.ShowAsync` 的 effective 色 → 取色器初始值 + `IsPairReadable` 校验基线）
- 【触发条件】在设置窗口为浅色主题（或随记面板实际呈浅色主题）时，打开「功能格子 → 随记 → 记录配色」的取色器：① 取色器初始色恒为深色主题近似值；② 对比度校验以 0x282828 为"当前背景"——选一个在浅色卡片上可读但在深色上不可读的颜色会被**误拒**，反之在浅色卡片上不可读的组合可能被**误放行**。
- 【风险等级】P3
- 【潜在影响】浅色主题用户在设置入口得到错误的校验结论与初始值；格子内菜单入口（传 surface 实际生效色）与设置入口对同一提交可能给出不同结论，双入口语义出现漂移。实际显示后果被 DEF-013 应用点复检兜住（不可读组合最终回退跟随主题），故不升级。
- 【代码层面根因】设置窗口没有 surface 实例可取实际生效色，回退值直接取了深色面板的近似常量而未按当前 ActualTheme/窗口主题解析。
- 【代码证据】
  ```csharp
  // SettingsWindow.QuickCaptureColors.cs:87-94
  private Windows.UI.Color ResolveQuickCaptureEffectiveTextColor(WidgetConfig config)
  {
      return ... TryGetTextColorOverride(config, out var textOverride)

  // :96-103 背景回退恒 0xFF,0x28,0x28,0x28
  ```
- 【整改建议】按设置窗口 `ActualTheme` 解析 `TextFillColorPrimary`/`CardBackgroundFillColorDefault`（可复用 surface 的 `TryGetThemeColor` Color/Brush 双形态逻辑），使校验基线与当前主题一致。
