- **潜在影响**：与台账 DEF-035 同族（UI 线程同步等待），但被 1500/500/150ms 三重上限钳制；系统 resume/unlock 后若 hook 注册持续失败（如 win32k 资源受限），每次 `OnLifecycleRecoveryRequested`→`RefreshRegistration` 都会在 UI 线程空等 1.5s。已有异步变体 `TryStartAsync`（:275-322）但同步调用方未使用。
- **整改建议**：`RefreshRegistration` 改走异步链或在后台线程执行（与 `TrySetEnabledAsync` 对齐）；至少在 `TryStart` 失败路径的日志中标注 UI 线程等待时长。
