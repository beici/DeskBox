### 【LAY-09】边距对话框的取消恢复不感知折叠状态：对话框打开期间胶囊自动折叠后，取消会把"面板矩形"套回已折叠窗口并把面板位置写成胶囊放置

- 【位置】`src/DeskBox/Views/WidgetWindowBase.TitleAppearance.cs:573`（打开时捕获 `dialogInitialRect`）、`:593-619`（取消恢复）；`src/DeskBox/Views/WidgetWindowBase.Collapse.cs:553-569`（`RefreshCompactPlacementAfterBoundsMove` 对 `_targetCollapsed` 早退）、`:4295-4321`（`CaptureCompactPlacement` 的 DEF-065 面板重推导守卫要求 `!IsCompactBoundsStateActive`）；`src/DeskBox/Views/WidgetWindowBase.Bounds.cs:519-523`（`CapturePositionAnchor` 在折叠态直通 `CaptureCompactPlacement`）；`src/DeskBox/Views/WidgetWindowBase.Collapse.cs:4753-4771` + `src/DeskBox/Services/WidgetCompactInteractionPolicy.cs:168-177`（自动折叠不感知外部工具窗口）
- 【触发条件】Smart（或 Click 且 IsCollapsed=true）胶囊悬停展开 → 右键标题 → 「边距设置」打开工具窗口 → 指针移入对话框（外部窗口，不构成 `HasBlockingFlyoutOpen`，也不在 `CanAutoCollapse` 的任何阻断项内）→ 默认 200ms（`WidgetShellSettingsSlice.cs:203`）后 `SetCollapsedState(true)` 把窗口收成胶囊 → 用户输入触发预览（单格路径作用于静止胶囊，`ResolveMarginSubjectBounds` 因 `IsCompactBoundsStateActive=true` 返回 live 胶囊矩形）→ 点「取消」。
- 【风险等级】P2（Smart/Click 胶囊用户 + 停顿超折叠延时 + 取消的组合；Smart 为胶囊主用法，输入 3 位数即必然超 200ms）
- 【潜在影响】①取消恢复无条件 `SetWindowPos(dialogInitialRect)`——那是打开时捕获的**面板矩形**，被套到 `_targetCollapsed=true` 的窗口上：取消瞬间出现一个面板尺寸的"折叠态"窗口，直到下一次悬停展开/收起才恢复胶囊几何；②恢复内的 `CapturePositionAnchor` 在折叠态直通 `CaptureCompactPlacement(panelRect, persist:false)`，而 DEF-065 的面板尺寸重推导守卫恰以 `!IsCompactBoundsStateActive` 为前置——折叠态下守卫被跳过，**面板位置被原样写成胶囊放置**（正是 DEF-065 要堵的"以面板为基准锚定胶囊"形状，从另一个状态面复发）；③预览阶段已把放置推到预览位（`:816` `CaptureCompactPlacement(target, persist:true)`），取消既不回滚放置、`RefreshCompactPlacementAfterBoundsMove` 又对折叠态早退——下次收起/重启时胶囊吸附到取消前预览过的位置。

### 【LAY-10】`ApplyOwnMarginTarget` 的 `ReferenceEquals(subject, live)` 对两个值类型装箱比较恒为 false，预定的通用刷新分支成为死代码

- 【位置】`src/DeskBox/Views/WidgetWindowBase.TitleAppearance.cs:805-817`
- 【触发条件】单格边距应用路径每次执行（`ApplyOwnMarginToSide`/`ApplyOwnNearestMargin` 的唯一落点）。
- 【风险等级】P3（多数状态下 else 分支与预期输出等价甚至更优，见下；属逻辑缺陷而非可直接复现的功能损坏）
- 【潜在影响】`subject` 与 `live` 都是 `RectInt32` 结构局部变量，`object.ReferenceEquals` 各自独立装箱 → **恒 false**，f17d0528（DEF-065）设计的"`subject==live` 时走 `RefreshCompactPlacementAfterBoundsMove()`"分支永不执行。实际后果按状态分：①非折叠态（Click 持久展开）：本应经 `RefreshCompactPlacementFromExpandedBounds` 按 `WidgetCompactExpansionDirectionPolicy` 方向覆盖重推导胶囊，现在改为 `CaptureCompactPlacement(target, persist:true)` 按面板目标矩形反推锚点——全局展开方向覆盖与几何锚点不一致时，胶囊的下次收起位置会落在另一侧；且 `_stableCompactBounds` 被置为面板矩形而非胶囊矩形；②折叠态：else 分支反而补上了通用刷新会早退留下的放置 stale（意外收益）；③非压缩宿主（默认 Expanded，不用折叠）：`Config.CompactPlacement` 与 `_stableCompactBounds` 被写入并持久化全窗矩形（配置污染，无消费者，直到用户切换折叠行为）。

## 4. 观察项

1. **`DesktopIconGeometryService` 在 UI 线程同步跨进程读**（`DesktopIconGeometryService.cs:111-123,156-171`）：单次 `SendMessageTimeout` 120ms `SMTO_ABORTIFHUNG` 有界、 hung 的 Explorer 立即返回，512 项上限 + 1.5s 缓存（`:49-54`）；理论最坏（Explorer 慢而未 hang 时逐项 120ms）存在 UI 停顿面，实测设计（DEF-062 实机 24 项）远低于此。维持现状可接受，若未来加自动布局功能建议转后台预取。
2. **拖拽/缩放会话的吸附目标为开始时刻快照**（`ResizeGuideOverlayService.cs:693-696` `_dragSnapTargets` 仅 `BeginDrag` 采集，会话内不刷新）：拖动期间拓扑切换或对端窗口移动不参与吸附解析；上游 1.5.5 "snap-edge refresh" 仅为高亮视觉刷新，未改变该语义。低频、自愈（下次会话重采）。
3. **批量 transform 使用批前邻居快照**（`WidgetManager.BulkAppearance.cs:97-118` 先全量采快照再逐窗应用）：窗口 A 移动后，窗口 B 的"最近邻居"仍按批前几何解析，最终布局与逐窗串行重算可能不同。原子快照语义自洽，且应用后对话框即从实时几何回读（`SyncBoxesFromLiveMargins`），仅记录。
4. **`AssignNonOverlappingBounds` 以 `GetDpiForSystem()` 缩放 occupied 矩形**（`DesktopOrganizationCoordinator.cs:370-387`）：规划始终限定主屏工作区（`SPI_GETWORKAREA`），系统 DPI 在登录会话内等于主屏 DPI，故现有约束下自洽；仅当"主屏 DPI 会话中变更"或未来把规划扩展到副屏时才需改用 per-monitor scale。
5. **`PlaceDetachedMember` 级联落点不做工作区钳制**（`WidgetManager.Groups.cs:1965-1986`）：靠组坐标贴边 + 24..120px 级联可能瞬时越界，重启链 `EnsureVisible` 收敛；与 LAY-06（24px 不随 DPI）同址，若日后修 LAY-06 可顺带补 `EnsureVisible`。
6. **512632a2 的钳制展开提示为纯通知**（`WidgetWindowBase.Collapse.cs` 3211-3224 区段）：`layout.IsSizeConstrained` 时的 `ShowFeedback` 不做工作区查询、不影响展开启动时序，几何钳制本身在 `WidgetCompactExpansionCalculator.CreateCandidate`（`:160-215`）数学正确。

## 5. 小结

本专项完成格子布局全链路的 round-08 复审：**F5（DEF-008）修复与 DEF-062~065/N1 防线在当前树全部成立，无复发**；round-06 的 8 项立案复核为维持 3（LAY-05/06/07，均 P3 挂账）／复发 0／已消除 5（LAY-01/02/03/04/08）。1.5.5 合并（snap-edge refresh、widget-layout.json、Ensure→Derive+ResolveRequestedCompactExpansion 拆分）与 512632a2 对布局的影响面为视觉/持久化/提示层，几何路径未发现回归。

新立案 3 项：**P0×0、P1×0、P2×1（LAY-09，边距对话框取消恢复与胶囊自动折叠的状态不一致）、P3×2（LAY-10 值类型装箱比较恒 false 致分支死代码；LAY-11 批量边距对折叠源的跳过/测量语义偏差）**。主要风险集中在边距对话框与 Smart 折叠状态机的交界处——两个特性各自正确，但"对话框打开期间折叠状态可以翻转"这一事实未被取消恢复路径纳入，建议随下一个边距/胶囊修复批次一并闭环。
