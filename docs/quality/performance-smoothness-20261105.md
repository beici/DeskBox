# 2026-11-05 性能与流畅度专项

本轮针对文件格子滚动、展开收起动画、番茄钟后台刷新和背景图缓存，完成 10 个应用文件的修改，新增 30 项行为测试。沿用现有 WinUI、统一格子宿主和原生窗口提交路径，未增加第三方依赖或数据迁移。

## 修改与原因

| 路径 | 已确认的问题 | 本轮处理 |
| --- | --- | --- |
| 文件滚动 | 同一视口回调先补足列表，再根据尚未更新的滚动范围追加一批，重复重建列表并重启图标加载 | 合并成一次预算请求；临近末尾按 16～64 项预取；无剩余项时停止排队 |
| 文件布局 | 布局事件把 sender 当作列表，实际没有进入补足视口和重试订阅路径 | 在公共视口订阅一次布局事件，显式选择当前网格或列表；补回缺失的滚动容器订阅 |
| 文件名浮层 | 滚动时反复对已隐藏浮层停止动画 | 已隐藏且没有待恢复选中项时直接返回 |
| 番茄钟 | 原生窗口隐藏不会自动卸载 XAML，33ms 视觉计时器仍可能持续运行 | 适配器缓存并重放显隐、折叠和过渡状态；隐藏、折叠及窗口动画期间暂停视觉刷新；展开前准备当前帧，恢复后按真实时钟同步 |
| 番茄钟通知 | 每秒为 22 个属性发送通知，连未变化的阶段也触发宿主刷新 | 比较类型化状态快照；普通一秒计时仅通知倒计时、剩余时间和进度，无变化时不通知；保留后台 1Hz 完成判定 |
| 背景图缓存 | 多张图片同时加载时都无法淘汰，全部完成后没有再次执行容量限制 | 完成回调结束后重新淘汰；维持 8 项上限，保护仍在加载的条目、新旧加载身份和回调重入 |
| 动画缓冲区 | 静态列表保留最后一帧的窗口委托，动画结束后仍可持有窗口；每帧另建结果数组 | finally 清空引用；128 项以内使用栈上结果区，超出使用数组池并归还 |
| 动画准备 | 展开和托盘动画为诊断数据重复同步查询显示模式 | 与帧调度复用已有显示时序缓存，保留移动窗口前确定目标显示器的时机 |

## 性能证据及边界

读取用户已运行的 Debug 实例日志，保存了 16:39 的 10 次文件格子动画摘要。其中 5 次展开首帧等待为 16.2、16.5、51.7、35.6、158.5ms；摘要记录的最大单帧提交链路开销在 2.8～4.7ms 之间。该记录支持优先减少界面初始化和重复刷新干扰，但不能仅凭这些摘要精确归因所有掉帧。

修改前被动采样 20 次、跨度 19.33 秒：CPU 时间增加 0.140625 秒，最后私有内存约 365.1MiB，工作集约 519.8MiB。采样时未控制操作场景，这不是内存泄漏结论，也不是可用于计算前后收益的配对基准。

已通过的行为测试验证：

- 60 次正常番茄钟计时更新共 180 次属性通知；旧实现相同路径为 1,320 次。测试还覆盖完整轮次、设置、语言、分数秒、后台完成和重入。
- 12 个同时等待的背景图加载，在完成后无需新的读取请求即可回到 8 项缓存；回调异常、重入及替换不会误删新加载。
- 动画提交准备失败、完成回调异常以及数组池分支均能释放缓冲区中的委托；弱引用测试验证回调所有者可回收。
- 文件视口增大时先一次补足覆盖量，再根据新布局判断预取；尾部增长有上限，计数溢出受保护。

本轮未操作桌面界面，也未自动重启 DeskBox。因此没有声称实测 FPS、CPU 百分比或总内存下降幅度。冷展开首帧、滚动手感和偶发闪烁仍需要手动验收。

## 手动验收

1. 启动 `E:\DeskBox-debug\DeskBox.exe`，连续展开、收起多个格子，观察第一次展开和快速切换是否仍有明显停顿、闪烁。
2. 在文件较多的格子中持续拖动滚动条，滚到末尾再返回，切换网格/列表；确认项目能继续加载，文件名浮层及选中状态正常。
3. 启动番茄钟后折叠、隐藏，再重新打开；确认剩余时间正确，暂停/继续及阶段完成提醒正常。
