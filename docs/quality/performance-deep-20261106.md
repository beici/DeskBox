## 根因与实现

### 设置保存与分栈通知

普通设置保存会同步通知多个文件 ViewModel。原实现无条件解析分栈 metadata、重建投影，随后每个 StackItem 再发出一组固定属性通知，导致没有实际内容变化时仍刷新预览。

- `WidgetStackSettingsSnapshot` 保存有效分栈配置的独立快照，覆盖自定义规则、metadata、成员顺序及跟随全局标志。相同输入直接返回；布局使用独立的 11 值快照，尺寸变化仍然生效。
- 关闭投影时不扫描 Items、不排入无用重建；启用时使用当前 Items 构建。真正的成员及元数据变化继续走原有显式失效入口。
- `WidgetStackItem` 按成员身份序列、前四项预览、计数、展开及布局分别通知。相同更新发出零通知；不足四项时对应 getter 返回 null，能正确清除旧预览绑定。
- 文件表面补充监听预览尺寸相关属性，避免去掉宽泛通知后漏掉真实布局变化。

这是减少重复工作和通知扇出的改动，不把任意设置保存都宣称为常数时间。自定义规则及 metadata 的相等检查仍随输入规模增长；真正重分组继续承担原有分类和排序成本。

新增 66 项测试：设置快照 36 项、成员通知 30 项，覆盖不变更新、深层规则修改、成员顺序、空集合和布局差异。生产日志的 `stackProjectionRebuilds` 已不再计入关闭投影时的空调用，因此不能拿旧会话的重建计数直接推导下降比例。

### Todo / QuickCapture 标签恢复

原分段标签恢复可能在隐藏、未测量或零宽度状态下持续订阅全局 `CompositionTarget.Rendering`。现在由可见生命周期持有 `WidgetSegmentedRestoreSession`：

- 保留三个稳定帧及 0.5 px 容差，每次会话最多观察 12 帧。
- 隐藏、卸载和非法宽度立即注销；实际布局容器的 SizeChanged 驱动后续恢复。
- 预算边缘最后一次尺寸变化允许一次低优先级补偿重试，避免最后一个布局事件恰好落在会话结束处。
- Todo Adapter 转发可见性且不主动物化视图。卸载清除调整尺寸、响应式过渡及待处理布局标志，防止缓存组件重挂后被旧状态永久挡住。

新增 22 项会话行为测试和 7 项生命周期契约测试。12 帧预算约束一次恢复会话，不能理解为整个控件生命周期最多渲染 12 帧。

### 全景背景移动

原来每次原生窗口移动都写入 Image 的 Width、Height 和 Margin，将位置变化带入 XAML 布局。现在由 `WidgetPanoramaPlacementState` 区分尺寸与位置：

- 尺寸确实变化才写 Width / Height；位置通过复用的 TranslateTransform 更新。
- 第一次有效全景定位时才创建 Canvas，让超出格子的全景图获得完整布局空间；既有宿主继续承担裁剪。
- RectangleGeometry 复用，仅宿主真实尺寸变化时修改 Rect。
- 从 Shell 当前显示的全景 source 判断是否需要更新；切回普通背景后，缓存 source 不再触发无用原生几何读取。
- 保留跨显示器与混合 DPI 所需的实时窗口几何读取。

新增 15 项策略测试。1,000 次连续位置变化产生零尺寸更新，证明写入决策减少，不等价于已实测整个 XAML 树零布局或屏幕帧率提升。

### 隐藏窗口的层级收尾

采样发现：窗口即将隐藏时，通用 `ClearTopMost` 仍可能查找桌面宿主、重挂 Owner、置底，并触发可见兄弟背景刷新。这些工作与下一次显示的层级准备重复。

新增 `ReleaseHiddenWindowLayer`。两个隐藏入口先隐藏 HWND / AppWindow，再恢复 NOACTIVATE，并仅在实际 TOPMOST 时清除置顶；最后解除输入抑制。隐藏入口不再查找或重挂桌面宿主，也不重新置底。NOACTIVATE 不能省略，因为桌面固定模式的标题编辑会临时允许激活。

Owner 账本、关闭时恢复及通用 ClearTopMost 语义保持不变。下一次显示仍经过既有 prepared-show 入口选择层级。已交叉审查可见性消费者和两个显示入口，契约测试覆盖调用顺序、焦点样式恢复及禁止重挂。

剩余主要瓶颈仍是原生批量位置提交：修改后 Rendering 归属合计 650.747 ms，其中托盘 `EndDeferWindowPosNative` 为 533.617 ms，占本次记录内部约 82%。它包含 subclass 回入，不能一概归咎于系统调用 CPU。没有采用关闭重绘或停止复制窗口内容等未经验证的标志来掩盖开销。

前一轮报告中的 `maxCallbackMs` 已纠正为回调间隔。最大原生提交间隔还可能包含缓出末端整数像素不变及最后落点确认，不能把 85.4 ms 直接解释为中途冻结。本轮没有呈现时间戳、DWM/GPU 时间线证据，尚不能宣称 165 Hz 全程达标，也未将 private memory 波动定性为泄漏。
