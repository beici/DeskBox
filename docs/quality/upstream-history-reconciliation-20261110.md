## 原因与来源证据

发布前的本地开发分支已经合并过上述上游基线。本次发布为了审查完整代码并隔离未公开开发历史，将最终源码作为一个快照接在本仓库原有 `main` 上，遗漏了第二父提交。GitHub 按提交图计算同步关系，源码已经包含的上游变化因此仍计入 behind。

补齐前完成以下核验：

1. 取得完整上游历史，消除浅克隆对祖先关系和数量计算的影响。
2. 确认 `1fdf0bd9` 是发布来源开发分支的祖先；在该开发分支上再次合并此基线，Git 返回完全相同的源码树。
3. 按 Git blob 内容逐一核对发布树的 **2,237 个文件**与审查后的原工作区，缺失和不一致均为零。
4. 基于已核验的合并结果建立历史协调提交。合并前后的完整 Git tree 均为 `0954c01f0d7383d31a4ef13bf8e178e6825701f2`，因此没有重复应用上游补丁或撤销本地增强。
5. 只接入上游已公开提交与本次维护提交，不把原工作区的未发布开发提交设为父提交。配置、截图、原始诊断和构建日志不进入提交。

这里采用保留已核验源码树的历史合并，仅适用于“代码以前已经合入、发布快照遗漏了历史”的情况。不能用这种方式处理尚未采用的上游更新，否则会将未实施的变化错误标记为已合并。
